## 集群凭证管理与更新

kubeconfig 保存连接地址、认证身份及上下文。不同集群、账号和授权模式可能使用不同认证方式， 不能假定所有 UK8S 凭证都使用 Token，也不能假定刷新 Token 会使所有旧凭证失效。

获取和配置方法见[安装及配置 kubectl](/uk8s/manageviakubectl/connectviakubectl)。

### 一、确认凭证类型

在「概览」页，通过「APIServer」或「外网APIServer」旁的「凭证」查看当前账号的 KubeConfig。 本文所示控制台示例使用客户端证书。查看自己配置中的 `users[].user`
字段即可判断认证方式， 无需将字段值提供给他人。

| 字段                                            | 认证方式         | 更新时的关注点                 |
| --------------------------------------------- | ------------ | ----------------------- |
| `client-certificate-data` 与 `client-key-data` | 客户端证书及私钥     | 证书有效期、身份授权及平台提供的刷新或撤销机制 |
| `token`                                       | Bearer Token | Token 是否过期、被刷新或撤销       |
| `exec`                                        | 外部认证插件       | 由对应插件获取凭证，按该认证方案维护      |

![当前控制台内网凭证弹窗，配置内容已完整遮盖](/images/manageviakubectl/credentials-internal-current.png)

内网和外网表示不同的连接入口，不代表两套相互独立的访问身份。

### 二、子账号凭证更新

对于已开启授权管理的集群，主账号或具备相应权限的集群管理员可在「授权管理」中管理子账号的 独立凭证。具体角色要求、有效期设置、刷新与撤销操作见
[UK8S RBAC 授权管理](/uk8s/auth/rbac)。

1. 确认需要更新的子账号及集群，检查该凭证被哪些客户端或自动化任务使用。
2. 由管理员在「授权管理」中对目标账号执行相应的凭证刷新操作。
3. 由该子账号重新获取自己的 kubeconfig，更新本地文件和使用此凭证的自动化任务。
4. 显式指定新文件验证访问权限，例如：

```bash
kubectl --kubeconfig="$HOME/.kube/uk8s-demo.yaml" auth can-i get pods -n default
kubectl --kubeconfig="$HOME/.kube/uk8s-demo.yaml" get pods -n default
```

将命名空间替换为实际授权范围。失去业务访问需求时，应撤销对应授权；不要只删除本地配置文件。

### 三、历史 Token 凭证

如果历史集群仍提供「更新凭证」入口，且当前 kubeconfig 使用 `token`，应按该入口的提示更新。 更新后重新获取凭证，并同步替换使用旧 Token 的客户端及自动化任务。

此操作的失效范围是对应的 Token，不应将它当作客户端证书的吊销机制。 如果当前控制台没有此入口，请按当前授权模式处理，不要沿用旧截图的位置操作。

### 四、凭证泄漏与保管

- kubeconfig 中的 Token 和客户端私钥都是敏感信息；Base64 编码不等于加密。
- 泄漏后，先确定身份和权限范围。子账号可由管理员撤销授权；管理员证书或历史管理凭证应联系 集群管理员或技术支持确认适用的失效处理方式。重新复制配置文件本身不会使旧凭证失效。
- Master 节点上的管理配置可能使用另一套客户端证书，应单独保管，不能认为刷新控制台 Token 就会更新或撤销这套证书。
- 不要共用管理员凭证替代子账号授权。给日常操作分配所需的资源与命名空间权限。
- 展示截图时，遮盖完整凭证正文，以及账号、集群标识、IP 和网络资源标识。

认证方式的背景说明见
[Kubernetes 用户认证](https://kubernetes.io/docs/reference/access-authn-authz/authentication/)。
